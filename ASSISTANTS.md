# Contribute through your assistant

Multivac's MCP bridge gives an assistant tools to discover projects, reserve work,
read project context, and return findings. Your harness controls the model and its
execution tools. This works with local models and hosted providers through an
assistant that supports local MCP servers over stdio.

## Connect

Run `uv run multivac-client dashboard` and choose **Use my assistant**. Request a
connection, send the public pairing code to the pilot owner, and check approval.
Select your harness and follow the generated instructions. These include the
installed Python path and your selected Multivac connection; they contain no
credentials. Keep the client installed at that location. Regenerate the setup if
you move its environment or choose another connection.

| Assistant | Setup generated by Multivac |
| --- | --- |
| [Claude Code](https://code.claude.com/docs/en/mcp) | `claude mcp add` command with local project scope. |
| [Qwen Code](https://qwenlm.github.io/qwen-code-docs/en/users/features/mcp/) | Entry to merge into the project's `.qwen/settings.json`. |
| [Kimi Code](https://moonshotai.github.io/kimi-code/en/customization/mcp) | Entry to merge into the project's `.kimi-code/mcp.json`. |
| [Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) | `codex mcp add` command for its saved configuration. |
| Other MCP harness | A stdio command and argument list in `mcpServers` format. |

Preserve existing settings when adding an entry. Start a new assistant session
after configuration. The dashboard's **Test MCP bridge** button initializes the
installed bridge and lists its tools. It makes no model requests and does not
contact Multivac or a research project. A successful check establishes that the
bridge starts; use the connection-check prompt in your assistant to verify its
configuration and approved project access.

The setup formats follow the linked harness documentation. Automated checks cover
the actual stdio bridge and a complete synthetic contribution cycle. Execution
inside each named harness remains unverified.

Terminal equivalents:

```sh
uv run multivac-client assistant-config --harness claude-code
uv run multivac-client check-assistant
```

Other `--harness` values are `qwen`, `kimi`, `codex`, and `custom`. Omit the option
to print all profiles. The global `--origin`, `--connection`, and `--data-dir`
options select the platform and saved connection before the subcommand.

## Give it work

The dashboard includes an editable contribution request. For example:

> Explore my approved projects and spend up to ten minutes on a useful research
> contribution. Use my current model and tools. Inspect the task first and respect
> my data-access permissions. Return findings and limitations, then show me the
> project's receipt and any review still needed.

Set model access, tool permissions, and spending limits in your harness or provider
account. Multivac records the resource offer and checks the project's task against
it. The bridge does not sandbox the assistant or enforce its model spending.
Project context supplies research material; it does not authorize access to local
data or additional resources.

The assistant can call `connection_status`, `list_projects`, `offer_resources`,
`inspect_contribution`, `save_project_context`, `start_contribution`,
`return_result`, `recover_result`, and `cancel_contribution`.
`link_my_device` can link a device you identify to the same contributor identity.
Reuse the request ID when retrying a reservation so an uncertain response does not
create another task.

## Keep the result and receipt

`return_result` saves the artifact and reported usage on this device before
delivery. A retry uses that same result. A different result under the same
contribution ID is rejected to preserve the original evidence.

After an interrupted delivery, ask your assistant to call `recover_result` with
the contribution ID, use **Recover saved result & receipt** in the dashboard, or run:

```sh
uv run multivac-client collect CONTRIBUTION_ID
```

If delivery is still pending, inspect it later with
`uv run multivac-client inspect CONTRIBUTION_ID`. The client saves the full project
receipt when it becomes available. Recovery makes no model request and does not
repeat the research. The receipt may acknowledge evidence awaiting scientific
review; its meaning follows the project's acceptance rules.

Cancelling releases the platform reservation. Also stop any work your assistant
is running locally. Keep saved findings, usage, and receipts after interruption;
see [privacy and data flow](PRIVACY.md) for storage details.
